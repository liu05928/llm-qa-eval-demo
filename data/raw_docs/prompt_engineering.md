# Prompt Engineering 入门介绍

Prompt Engineering 通常翻译为提示词工程，指的是通过设计输入给大模型的提示词，引导模型按照指定目标、格式和风格生成回答。

在大模型应用中，Prompt 不只是简单的一句话问题。一个较完整的 Prompt 通常会包含角色设定、任务说明、输入内容、输出格式要求、限制条件和示例。

例如，在教育解释场景中，可以要求模型扮演“耐心的老师”，用通俗语言解释概念，并分步骤说明。在论文总结场景中，可以要求模型从研究背景、方法、实验、结论和不足几个方面进行总结。

第一周项目中已经设计了 mode 参数，包括 general、education 和 paper_summary 三种模式。这个设计体现了 Prompt 模板管理思想：不同任务使用不同模板，而不是所有问题都用同一种提示方式。

Prompt Engineering 的作用包括：

1. 控制回答风格；
2. 规范输出格式；
3. 降低模型答非所问的概率；
4. 提高复杂任务的稳定性；
5. 让系统更容易接入接口和前端；
6. 为后续评测提供统一输出结构。

在 RAG 系统中，Prompt Engineering 更加重要。因为系统需要告诉模型：回答必须优先依据检索到的参考资料。如果参考资料没有相关信息，就应该明确说明资料中未提及，而不是编造答案。

一个好的 RAG Prompt 通常会包含：

1. 角色：你是一个知识库问答助手；
2. 资料约束：请严格根据参考资料回答；
3. 缺失处理：资料没有提到时，不要编造；
4. 输出要求：回答要清晰，可以分点；
5. 来源要求：最后给出参考来源。

因此，Prompt Engineering 是大模型应用开发中的基础能力，也是 RAG 和 Agent 项目的重要组成部分。
