# Training Reproduction

This directory contains the public training configuration for the education-domain trusted QA system. It keeps the reproducible parts of the fine-tuning setup: dataset registration, LLaMA Factory YAML configs, serving configs, and metric summaries.

Model weights, adapter weights, checkpoints, tokenizer dumps, and temporary run folders are intentionally excluded from the public repository.

## Included Assets

- `llamafactory/dataset_info.json`: dataset registration for LLaMA Factory.
- `llamafactory/qwen25_3b_lora_sft.yaml`: LoRA SFT config.
- `llamafactory/qwen25_3b_qlora_sft.yaml`: QLoRA SFT config.
- `llamafactory/qwen25_3b_qlora_sft_v2.yaml`: v2 QLoRA config.
- `llamafactory/qwen25_3b_qlora_sft_v21.yaml`: v2.1 QLoRA config with best-checkpoint selection.
- `llamafactory/qwen25_3b_lora_api.yaml`: LoRA serving config.
- `llamafactory/qwen25_3b_qlora_api*.yaml`: QLoRA serving configs.

## Dataset Snapshots

The SFT data is generated by scripts in the repository root:

```bash
python3 sft_dataset_builder.py
python3 sft_dataset_builder_v2.py
python3 sft_dataset_builder_v21.py
```

Current dataset versions:

| version | total | train/dev/test | notes |
| --- | ---: | --- | --- |
| v1 | 184 | 155/15/14 | First small-scale validation set. |
| v2 | 2400 | 1920/240/240 | Larger education QA dataset. |
| v2.1 | 3000 | 2400/300/300 | Adds hard-refusal and anti-repetition patches. |

v2.1 contains 480 hard-refusal samples and 120 anti-repetition samples while preserving source-level train/dev/test splitting.

## Recommended Training Commands

For lower-VRAM environments, use QLoRA:

```bash
llamafactory-cli train training/llamafactory/qwen25_3b_qlora_sft_v21.yaml
```

For larger GPUs, LoRA can be used:

```bash
llamafactory-cli train training/llamafactory/qwen25_3b_lora_sft.yaml
```

The configs assume the dataset files are available under the repository `data/` directory. If training from a separate LLaMA Factory checkout, keep the same relative directory layout or update `dataset_dir` in the YAML config.

## Serving A Fine-Tuned Adapter

After training, serve the adapter with an OpenAI-compatible API:

```bash
API_PORT=8001 llamafactory-cli api training/llamafactory/qwen25_3b_qlora_api_v21.yaml
```

Then set the local app to use:

```text
USE_MOCK=false
GENERATION_BACKEND=local_sft
LOCAL_SFT_BASE_URL=http://127.0.0.1:8001/v1/chat/completions
LOCAL_SFT_API_KEY=EMPTY
```

The app can then call the fine-tuned backend through `/chat`, `/rag_chat`, and `/agent/chat`.

## Evaluation Snapshot

SFT generation quality:

| run | avg keyword | citation complete | structure complete | repeated sections | refusal correct |
| --- | ---: | ---: | ---: | ---: | ---: |
| v2 QLoRA fixed50 | 0.7600 | 1.00 | 1.00 | n/a | 0.0000 |
| v2.1 QLoRA fixed50 | 0.8317 | 1.00 | 1.00 | 0.00 | 0.0909 |
| v2.1 QLoRA hard-refusal100 | 0.6225 | 1.00 | 1.00 | 0.00 | 0.9300 |

Main interpretation:

- v2.1 improved fixed-set keyword coverage while preserving citation and structure stability.
- The hard-refusal patch improved dedicated unsupported-question refusal behavior.
- Remaining generalized unsupported-question cases are handled jointly by SFT behavior and the RAG/Workflow `context_guard.py` gate.

Detailed reproduction steps are documented in `docs/reproduce.md` and `docs/training_reproduction.md`.
